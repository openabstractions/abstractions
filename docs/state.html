Downloads That Survive

A standard library of interfaces — SLF4J's idea applied to the things every local-AI tool rebuilds badly and privately.

2 September 2026 9,629 lines Go · Python · C++ 2 machines, 3 tiers

Every local-AI tool ships its own downloader, and every one of them loses a 40 GB model when the machine sleeps. Every tool keeps its own store, so the same weights sit on disk four times under four names.

Measured on one ordinary machine: 116 GB across four stores that cannot see each other. Not because the problem is hard — because there is no shared interface, so each tool solves it privately and none of them solve it well.

The shape

Two hops, each ignorant of the next

An application asks for bytes. It never chooses who fetches them — it asks one question, is a system downloader alive on this machine, and that service decides everything after. Exactly as a library that logs knows about a facade and a default, and nothing about which collector the sinks point at.

Go and Python finish each other's downloads

Resume uses what was proven, not what is on disk

A real download killed with SIGKILL. The dead process had written more than it had checkpointed; nothing vouches for the difference, so the resume discards it. That gap is the design, not a rounding error.

O_EXCL is genuinely exclusive over SMB

The assumption the entire lease protocol rests on. If two machines could both succeed at creating the same epoch token, two owners would write one file. Tested against the real Synology rather than assumed.

Go writes it, C++ serves it, Python reads it

A job record written by the Go tool is rendered by the forked Lemonade server on /api/v1/downloads — from disk, not from its own memory — and read back by the Python implementation from the same directory. Three languages, one contract, one real application.

A client claiming to be systemd with uid 0 is stamped with what SO_PEERCRED actually reports — and its lie is kept, in the field documented as a claim. Deleting it would destroy evidence; believing it would be the bug.

Inventory

What actually exists

The bar this project set: an interface with one implementation is a design. It becomes an abstraction when something written independently passes the same tests and can pick up work the first one started.

LayerLanguagesStatusWhat it is
jobGo · Python Abstraction Work that outlives the process that started it. Leases, epochs, checkpoints.

Direction

Where this is heading

In order, because each one answers a question the previous one cannot. The numbering is a dependency chain, not a priority list.

01

Propose it upstream

Not started

The fork builds and runs, but a fork is not adoption — we wrote both sides. The change has never been put to the people who maintain Lemonade.

Answers: does anyone who is not us want this?
02

The layers above job

One language each

Only job has three implementations. download has two and logging has one, so the argument thins out as you go up.

Answers: does the contract hold where the domain gets specific?
03

Storage as the second abstraction

Written, unwired

The vault exists and refuses corrupt files. Wiring it under download makes the 116 GB problem a stat rather than four copies.

Answers: does the pattern generalise past moving bytes?
04

One host that never serves chat

Untouched

From the original problem statement, and still unaddressed: too many hosts, and LLM hosts differ from video-model hosts where there should be one.

Answers: the third of the owner's three original problems.

Method

Rules, each earned by a specific failure

  • No interface until two implementations exist — and find the second one in the world rather than inventing it.
  • Prefer adopting or wrapping over building. BITS was adopted. slog was adopted. aria2 was refused on licence, and the reason is written down.
  • An interface changes on a failing real case, never on an argument. Finalize gained a parameter because a NAS could not discover a local destination from a handle — not because it read better.
  • Done means it runs on a machine you do not own, from the written instructions.
  • Every task ends in a pasted terminal transcript. A failure is a result.
  • The word "standard" is not used until somebody who is not us has implemented one.
